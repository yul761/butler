# BTL-245 信箱：实现计划

设计：`docs/superpowers/specs/2026-11-20-btl-245-mailbox-design.md`。每一步先写测试再写实现（TDD），做完一步提交一次。

1. **数据**：在 `db/migrations.ts` 末尾追加 `session_messages` 表和索引；写 `db/session-messages-repo.ts`，带单元测试：
   - 按 ref 去重并替换正文；
   - 三种状态的转换；
   - 按目标列出排队中的消息；
   - 按范围列出最近的消息；
   - 清理旧消息。
2. **共享常量** `src/shared/mailbox.ts`：
   - 投影文件的命名和后缀（`.json` / `.taken-<pid>` / `.done` / `.main`）；
   - 单次送出的上限（9,000 字符）；
   - hook 命令生成函数 `mailboxHookCommand`，有测试。
3. **hook 模式** `hook/mailbox.ts` + `entry.ts`：认领文件、拼正文、输出 additionalContext、改成 `.done`、写 `ShipherdMailbox` 信封；Agent/Task 跳过。单元测试用临时目录。
4. **hook 配置**：`project-mcp.ts` 的 PostToolUse / PostToolUseFailure 加信箱 hook（matcher `""`），PostToolUse 加 `mcp__shipherd-feature__remember` 的信封 hook；`shipherd-hook.ts` 裁剪 remember 的载荷。改测试。
5. **信箱服务** `src/main/mailbox/mailbox.ts`，有单元测试：
   - `enqueue`、重建投影、清扫 `.done` 和过期的 `.taken`；
   - 直接输入（认领 `.main`）、interrupt；
   - 等回复和送回 reply；
   - 送达回调（按 kind 分发）；
   - 列表视图、清理旧消息。
6. **约定广播** `src/main/mailbox/broadcast.ts`：识别 remember 信封，按 feature 找目标，排 `convention` 消息。有测试。
7. **改路径**，每一条都删掉旧代码、改测试：
   - `InboxService` 的汇报和回答；
   - `PreReviewService.deliver`；
   - `CommentLoop.deliverPr`；
   - Shipherd 总控 `send_message`（删掉 `ShipherdMessages`）；
   - `list_inbox` 的 messages。
8. **新工具**：`sessions-server.ts` 的 FEATURE_TOOLS 加 `send_message`（中英两份）；`control-handler.ts` 处理它；Shipherd 的 `send_message` 加上 `interrupt`。改测试。
9. **装配**：在 `index.ts` 里创建信箱，并接上：
   - hook 收件箱（`ShipherdMailbox`、remember 信封）；
   - `sessionStopped`、终端打开和退出；
   - 调度 tick；
   - 启动时清掉旧的投影目录。
10. **界面**：
    - IPC `messages:list`；
    - `MessageList` 组件，Shipherd 页和 feature 页「总控」tab 都用；
    - 中英文案。
11. **fake-claude + e2e**：`/fake-tool` 跑 PostToolUse 并记下收到的 additionalContext；e2e 走完一遍：总控发消息，在忙的 ticket session 在下一次工具调用时收到，界面显示「已送达」。
12. **文档**：README 中英两份改写「通信」一条；configuration 不涉及（没有新设置）。
13. **实测**：信箱为空、不空两种情况下 hook 的耗时（macOS），数字写进 PR。
14. 本地检查（typecheck、lint、test、e2e），派 Opus 子代理 review，处理意见，开 PR。
