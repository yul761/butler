# 中英文切换（设计）

来源：2026-10-26 用户请求：Butler 要给用英文的同事用。作为 patch 版本 1.2.1 发布。

## 用户确认的决定

- 两种语言：中文、英文。
- 默认跟操作系统的语言，之后可以在设置里改。
- 不只是界面：发给 claude 的提示词（handoff、刷新、今日重点、记忆）也跟着切换，生成出来的内容就是那种语言。用户在设置里自定义过的提示词不覆盖。
- 版本：1.2.1。

## 我的决定（用户看过复述，说“没问题”）

- 系统语言是中文（`zh` 开头，简体繁体都算）用中文，其他一律英文。
- 老用户（升级前已经完成向导或者有 ticket）保持中文：迁移 7 给他们写入 `language = zh`。新安装是 `auto`。
- 设置 → 常规加“语言 / Language”（自动 / 中文 / English），首次启动向导第一步也放一个。切换后马上生效（窗口重新加载，不用重启 Butler，终端照常重新连上）。
- 已经生成的内容（旧的 handoff、记忆、简报）不翻译，保持原来的语言。

## 实现要点（builder 的决定）

- 设置 `language`：`auto | zh | en`，可编辑、校验。解析顺序：环境变量 `BUTLER_LANG`（`zh` / `en`，给 E2E 和需要强制语言的人用）→ 设置 → `auto` 时取 `app.getPreferredSystemLanguages()` 的第一个。
- 共享：`src/shared/i18n.ts`：`Lang = "zh" | "en"`、`resolveLang(setting, systemLocales, override?)`。
- 主进程：`src/main/i18n.ts` 持有当前语言（`currentLang()` / `setLang()`），启动时和保存 `language` 后更新；保存后托盘菜单重建、通知渲染进程。主进程给人看的文案（系统通知、托盘、对话框、所有 `TicketError` / `SettingError` 的消息、git 失败、清理原因、control 返回给总控的错误）集中到 `src/main/strings.ts`，按语言各一套，类型保证两套键一致。
- 渲染进程：`strings.ts` 分成 `zh` 和 `en` 两套（同一个类型），`S`、`STATUS_LABEL` 是可重新赋值的导出；`main.tsx` 渲染前向主进程要语言。改语言后 `location.reload()`。
- 提示词：`handoffPrompt` / `refreshPrompt` 的默认值按语言；存的值等于任何一种语言的默认值时视为没改过，跟着语言走。handoff 的 schema 说明和例子、`/handoff` 命令正文、“今日重点”的系统提示、Butler 写进记忆的 follow-up / 决策标签、总控交任务的开头、`butler-sessions` 的工具描述（mcp 配置里传 `BUTLER_LANG`）都按语言。
- `/handoff` 命令：只有和当前语言版本一字不差才算 `installed`；另一种语言的 Butler 版本算 `stale`，环境检查提示修复（不自动改用户的 Claude Code 配置，和 README 的承诺一致）。
- 日期时间格式本来就用系统 locale，不动。
- StateCore 自己的蒸馏提示词在依赖库里，不在范围内。

## 不做

- 第三种语言、翻译已有数据、按 ticket 设语言。

## 测试

- 单测：`resolveLang`；迁移 7；`language` 设置校验；中英两套文案键一致（类型 + 一个运行时检查）；提示词默认值随语言切换、自定义的不变；`/handoff` 命令状态；主进程错误在英文下是英文。
- E2E：现有的用 `BUTLER_LANG=zh`；新加一个：英文启动 → 界面是英文 → 设置里切到中文 → 界面变成中文。
