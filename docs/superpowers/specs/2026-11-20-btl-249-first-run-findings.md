# BTL-249 新用户第一次使用：问题清单

日期：2026-11-20。目标：一个从没装过 Butler 的人，5 分钟内跑起第一个 ticket session。

## 怎么走的

- 用 e2e 沙盒模拟一台全新的机器：临时的 HOME、BUTLER_HOME、CLAUDE_CONFIG_DIR、TMPDIR；PATH 里只有假 claude；登录 shell 是假的，不读开发者的 shell 配置。全程没有读写真实的 `~/.butler` 和 `~/.claude`。
- 用 Playwright 驱动 Electron，每一步截图并保存页面文字。走的路线是：第一次启动 → 向导（语言、claude、hook、tracker、权限档案、完成；这是改之前的五步）→ 首页 → 新建 ticket（带仓库）→ 终端页签开 session → 让假 claude 提一个问题 → 首页「轮到你」出现一张卡片。
- 中文和英文各走一遍。不顺利的路线：PATH 里没有 claude；claude 没登录（只看代码，假 claude 模拟不了登录界面）；没装 gh、gh 没登录（只看代码和设置页）；选的目录不是 git 仓库；目录不存在；Windows 路径（只看代码）。

严重程度：**阻断**：新用户自己过不去；**高**：能过去，但很可能走错或放弃；**中**：困惑、多走弯路；**低**：文案或观感问题。

## 要定的事

第 10 条是流程改动，问过协调人，用户选了推荐的做法（2026-11-20）：

- 第一次的向导只留三步：检查 Claude Code（连同登录、gh）→ 装 hook → 完成。tracker 的 MCP 工具和权限档案留在设置页，完成页写清楚各在 设置 › 高级 › 定时与状态、设置 › 高级 › 打断与通知。
- 以前停在这两步上的人（本机记着的步骤是 `tracker` 或 `permissions`），下次打开向导直接到「完成」：前面两步已经走过。
- 向导失败的每一步加「卡住了？告诉我们」的反馈链接由 BTL-254 在这之后做，这里不做。

## 新加的 e2e

`e2e/first-run.spec.ts`「全新环境第一次使用」：沙盒里 claude 不在 PATH、在 `~/.local/bin`（回退位置能找到）→ 向导提示没登录 → 写入登录记录后重新检查提示消失 → gh 没登录（Windows 上：没装）的提示 → 「安装并继续」直接到完成页 → 完成向导 → 首页新建 ticket（不填仓库）→ 概况提示先添加仓库 → 添加仓库 → 「开第一个 session」→ 假 claude 提问 → 首页「轮到你」有一张卡片。

claude 不在 PATH 靠的是沙盒的新选项 `claudeOffPath`：假 claude 放在沙盒 HOME 的 `~/.local/bin`，启动前的守卫改成要求 PATH 里一个 claude 都找不到，并且 HOME（Windows 上 USERPROFILE、APPDATA）都在沙盒里。Windows 上回退找的是 `claude.exe`，假 claude 做不成 exe，这个选项在 Windows 上不生效，其余步骤照走。

## 自查后留下的

- gh 2.17 以前没有 `gh auth token`，会被当成「没登录」。提示里的 `gh auth login` 对这些人没用，但 gh 2.17 是 2022 年的版本，先不区分。
- 「轮到你」里不到一分钟的 review 行只写「刚刚」，不写「刚刚问的」。
